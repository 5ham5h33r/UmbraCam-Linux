is therefore not considered reliably validated.

## Repeating the stream tests

Build with `scripts\build-native.ps1`, then use Windows PowerShell:

```powershell
.\scripts\test-camera-streams.ps1 -Camera normal
.\scripts\test-camera-streams.ps1 -Camera component
# Only after installation and with UmbraCam running:
.\scripts\test-camera-streams.ps1 -Camera virtual
```

The runner enforces a 20-second deadline and terminates only its own test
process if capture hangs. stdout/stderr logs are kept under the ignored
`build` directory. The virtual stream test alone does not distinguish IR
content from the component's placeholder: final validation must also confirm
that the publisher updates the shared frame transport.

Testing uncovered a PowerShell process exit-code handling problem. The runner
and installer now cache child process handles before waiting so the real exit
code remains available after a fast process exits.
